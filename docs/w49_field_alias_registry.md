# Бэклог: единый реестр алиасов полей контрагента

**Статус:** не в v1.2.1 · поставить отдельной маленькой задачей  
**Контекст:** W-49, патч связей карточка ↔ комплект ↔ импорт ↔ DaData (v1.2.1)

## Проблема

Пять дефектов «тихой потери данных» имели один корень: алиасы
(`юр_адрес` / `адрес_заказчика`, `бик` / `бик_заказчика`, `паспорт_кем_выдан` /
`паспорт_выдан`) разрешались в четырёх местах по-разному:

1. `core_from_counterparty` / `counterparty_from_core` (prefill / upsert)
2. `_SYNONYMS` + `_journal_fields_from_context` (импорт)
3. `DADATA_FIELDS` + `form-assist.js` (подсказки)
4. `upsert_counterparty` (запись в карточку при генерации)

Патч v1.2.1 выровнял поведение точечно; без единого источника правды регрессии
вернутся при следующем синониме.

## Предложение (по образцу NAV_REGISTRY)

- Реестр в ядре или `web/app/services/field_aliases.py`:
  `CANONICAL_KEY → tuple[alias, …]` для всех `FIELD_KEYS` карточки.
- Importers / package_master / form_assist / JS apply* читают только реестр.
- Один тест-контракт: заполнить карточку уникальными маркерами во всех
  `FIELD_KEYS` → карточка → мастер → генерация → upsert → карточка; каждый
  маркер на месте. Заменяет россыпь точечных assert’ов.

## Критерий готовности

- Новый алиас добавляется в одном месте.
- Контрактный тест красный, если любое из четырёх мест «забыло» ключ.
