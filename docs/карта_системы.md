# Карта системы Док.Москва — структура, связи, перелинковка, проблемы

Документ для последующего анализа архитектуры и UX/SEO-перелинковки.  
Актуален на состояние репозитория после W-00…W-25, nav-order, образцов лендинга и ревизии прод-дыр (PR audit).  
Источник правды по коду: `web/`, `core/`, `deploy/`, `docs/`.

---

## 0. Краткий вердикт

Один FastAPI-процесс обслуживает **два логических хоста** (`dok.moscow` — публичный слой, `app.dok.moscow` — кабинет/админка).  
Функционал кабинета **орг-центричен** (`org_id` на сущностях + `FILES_ROOT/{org_id}`).  
Связанные контуры: документы ↔ комплект ↔ контрагенты ↔ журнал ↔ календарь ↔ биллинг.  
Изолированные/слабо связанные контуры: законодательство (`/zakon`), админка сервиса, webhook Т-Кассы, мониторинг НПА.  
Главный разрыв перелинковки: **лендинг → app есть, app → лендинг почти нет**.

## 1. Архитектура репозитория

```
desktop-tutorial /
├── web/                 # FastAPI + Jinja2/HTMX + Alembic + SQLAlchemy 2
│   ├── app/
│   │   ├── main.py      # create_app, middleware, include_router, static
│   │   ├── routers/     # HTTP-поверхность
│   │   ├── services/    # бизнес-логика
│   │   ├── templates/   # Jinja2
│   │   ├── static/      # CSS/JS/samples/favicons
│   │   ├── models.py, navigation.py, deps.py, security.py, …
│   │   └── billing/     # Т-Касса, crypto, jobs
│   └── alembic/
├── core/
│   ├── docfiller_core/  # генерация DOCX, комплекты, фильтры (без tkinter)
│   └── Шаблоны/         # DOCX + contracts_registry.json

├── docs/                # ТЗ, безопасность, эксплуатация, эта карта

```

**Потоки данных**

```
Браузер
  ├─ dok.moscow  ─┐
  └─ app.dok.moscow ─┤→ Caddy → app:8000 (uvicorn)
                     │         ├─ PostgreSQL 16
                     │         ├─ Gotenberg (DOCX→PDF)
                     │         ├─ core/ (ro) + Шаблоны (RW для admin templates)
                     │         └─ FILES_ROOT=/srv/dok/files

```

| Пакет | Зависимость |
|--------|-------------|
| `web` → `core` | `CORE_PATH` / `sys.path`, шаблоны `TEMPLATES_DIR` |
| `deploy` → `web` | Docker image `web/Dockerfile`, entrypoint alembic+uvicorn |
| `scripts/make_samples` | core + Gotenberg → `web/app/static/samples/*.pdf` |

## 2. Топология хостов и деплоя

| Хост | Роль продукта | Фактически |
|------|----------------|------------|
| `dok.moscow`, `www.dok.moscow` | Лендинг, юр. страницы, `/zakon/`, SEO | Тот же `app:8000` |
| `app.dok.moscow` | `/login`, `/cabinet/*`, `/admin/*`, OAuth callback, webhook | Тот же `app:8000` |

Разделение **логическое** через `PUBLIC_BASE_URL` / `APP_BASE_URL` в шаблонах и письмах, не через разные сервисы.

**Compose:** `caddy` (:80/:443) → `app` (:8000) + `postgres` + `gotenberg` (fonts-liberation).  
**Секреты:** только `deploy/.env` (см. `.env.example`).

## 3. Слои доступа и изоляция

### 3.1. Роли

| Роль БД (`UserRole`) | Home | Доступ |
|----------------------|------|--------|
| `service_admin` | `/admin/` | Админка сервиса; `org_id` обычно `None` |
| `user` | `/cabinet/` | Кабинет своей организации |

В навигации (`NavRole`) есть `org_user` и `org_admin`, но **отдельного org_admin в БД нет** — всем пользователям с org выдаются обе роли (`navigation.py`). Пункт «Настройки» формально `org_admin`, фактически доступен всем в org.

### 3.2. Изоляция данных

- Запросы сущностей через `org_scope` / `get_*_for_org`.
- Файлы: `FILES_ROOT/{org_id}/…` и `…/templates/` для org DOCX.
- Сессия: `user_id`, `org_id`, `role`, `sid`, CSRF в session.
- Cookies: `dok_session`; опц. `dok_2fa_device`; опц. `SESSION_COOKIE_DOMAIN=.dok.moscow`.

### 3.3. Тарифные гейты

| Тариф | Суть |
|--------|------|
| `guest` | 3 документа/мес, водяной знак; платные разделы → upsell на `/cabinet/billing/` |
| `specialist` | Платный; party-check доступен |
| `organization` | Платный; + «Мои шаблоны», лимит пользователей (5) |

Бета: org без подписки → trial Organization до `BETA_TRIAL_UNTIL`.

## 5. Внутренняя перелинковка

### 5.1. Источник правды меню — `NAV_REGISTRY`

Файл: `web/app/navigation.py`.

- Меню кабинета/админки, глобальный поиск и sitemap-логика строятся из одного реестра.
- Поля: `key`, `title`, `url`, `synonyms`, `roles`, `tariffs`, `area`, `group`, `menu`, `quick_action`.
- Upsell: пункт виден guest’у, но `url` подменяется на `/cabinet/billing/`.
- Порядок: `POST /api/nav-order` + `nav-sortable.js` → JSON в `users.nav_order`.
- Техмаршруты вне меню — `ROUTE_EXCEPTIONS` (тест `test_registry_covers_app_routes`).

**Сайдбар кабинета (menu=True):**  
Документы → Комплект → Мои шаблоны* → Контрагенты → Проверка контрагента* → Журнал → Календарь → Тариф и оплата → Настройки  
(\* тарифный гейт)

**Сайдбар админки:**  
Обзор → Организации → Пользователи → Заявки → Приглашения → Шаблоны → Платежи → Платёжная система → Статус

### 5.3. Связанный функционал (данные + UI)

| Контур | Связи |
|--------|--------|
| **Документы ↔ Комплект** | Общие шаблоны core, `allocate_number`, `Document`, лимиты генерации, watermark |
| **Комплект ↔ Контрагенты** | upsert CP из мастера; prefill из карточки; `package/repeat` |
| **Party-check ↔ Контрагенты ↔ Комплект** | save/update CP, session в package, журнал проверок |
| **Журнал ↔ Документы/Комплект** | список, download, repeat |
| **Комплект/CP ↔ Календарь** | автособытия сроков; ручные события с привязкой CP |
| **Всё генерационное ↔ Биллинг** | `assert_can_generate`, paywall party-check/templates, upsell в поиске |
| **Settings ↔ Auth** | 2FA, пароль, link/unlink Яндекс; политика require_2fa из PaymentSettings |
| **Leads ↔ Invites ↔ Users ↔ Orgs** | воронка админки |
| **Admin templates ↔ Documents/Package** | общий каталог `core/Шаблоны` |
| **Org templates ↔ Documents** | только тариф Organization, файлы org |

### 5.4. Изолированный / слабо связанный функционал

| Контур | Почему изолирован |
|--------|-------------------|
| **Законодательство `/zakon`** | Публичный контент; связь с кабинетом — редкая ссылка из `document_form`; мониторинг/поиск НПА фоном |
| **Webhook `/billing/webhook`** | Без UI-сессии; только Т-Касса |
| **Legal monitor / loaders** | Фоновые jobs + SMTP админу; нет кабинетного CRUD UI |
| **Глобальный поиск API** | UI-палитра; дублирует частично `/cabinet/search` |
| **Nav-order API** | Персонализация UI, не бизнес-данные |
| **Probe `/cabinet/org/{id}`** | Тестовая заглушка изоляции |
| **Статика samples** | Только лендинг; не связана с живыми документами пользователя |
| **Метрика** | Только лендинг (скрипт + CSP) |

### 5.5. Перелинковка в шаблонах (важное)

**Лендинг → app**

- `{{ app_base_url }}/login` — nav, hero, footer, 404, contacts, requisites  
- `{{ app_base_url }}/cabinet/billing/` — страница тарифов  
- якоря `/#apply`, `/#samples`; samples → `/static/samples/*.pdf`

**Лендинг ↔ себя**

- nav/footer: `/`, `/zakon/`, `/tariffs`, `/offer`, `/privacy`, `/requisites`, `/contacts`  
- sitemap/canonical через `public_base_url`

**App → лендинг**

- **Практически отсутствует** (нет «На сайт» в cabinet/admin/auth).  
- Из формы документа — относительный `/zakon/{slug}` (на origin app, не `public_base_url`).

**HTMX**

- `hx-boost` на body/sidebar; suggest: `hx-get` `/cabinet/counterparties/suggest/{party,address,bank}`  
- `hx-post` в шаблонах почти нет (обычные form POST).

## 6. Внешние связи и перелинковка

| Система | Направление | Где в продукте | Конфиг |
|---------|-------------|----------------|--------|
| **Яндекс OAuth** | OUT authorize/token/info; IN callback | `/auth/yandex/*`, settings security | `YANDEX_CLIENT_*`, `YANDEX_REDIRECT_URI` → **должен быть app-хост** |
| **Яндекс Метрика** | Браузер → mc.yandex.ru | Лендинг | `YANDEX_METRIKA_ID` + CSP |
| **DaData** | OUT HTTPS suggestions/findById | counterparties, party-check | `DADATA_KEY`, daily limit |
| **Gotenberg** | OUT Docker HTTP | PDF документов/комплектов/карточек | `GOTENBERG_URL` |
| **Т-Касса** | OUT Init/GetState/Charge; IN webhook | billing UI + `/billing/webhook` | ключи в `PaymentSettings` (Fernet) |
| **SMTP** | OUT | сброс пароля, лиды, биллинг/календарь/НПА письма | `SMTP_*`, `ADMIN_NOTIFY_EMAIL` |
| **publication.pravo.gov.ru** | OUT (часто HTTP) | мониторинг НПА | `PRAVO_PUBLICATION_BASE` |
| **ИПС pravo.gov.ru** | OUT | загрузка текста акта | `PRAVO_IPS_BASE` |
| **Google Fonts** | Браузер | landing + app CSS | CSP allowlist |
| **mailto** | Внешние | `hello@`, `privacy@`, `post@use.moscow` на LP | шаблоны |

**SEO внешнее:** `robots.txt` Allow `/`, Disallow `/cabinet`, `/admin`, `/invite`, `/apply`, `/login`; Sitemap на `dok.moscow`.

**CSP (`main.py`):** `default-src 'self'`; fonts/styles Google; scripts Метрика; `form-action 'self'` (оплата только через свой POST + redirect).

## 7. Модель данных (org-centric sketch)

```
organizations ─┬─ users (org_id nullable)
               ├─ invites
               ├─ counterparties ─┬─ contracts ── documents
               │                  ├─ party_checks
               │                  └─ calendar_events
               ├─ documents
               ├─ counters (PK org_id+key)
               ├─ subscriptions → tariffs
               ├─ payments
               ├─ calendar_events
               └─ events (audit)

users ─┬─ oauth_identities
       └─ password_reset_tokens

            ├─ legal_search_docs
            └─ act_watch_log
```

Файлы вне БД: `FILES_ROOT/{org_id}/…`, org templates + registry; сервисные шаблоны в `core/Шаблоны/`.

## 8. Сессии, безопасность, кросс-хост

| Механизм | Поведение |
|----------|-----------|
| Session | SameSite=Lax; `SESSION_HTTPS_ONLY` на проде |
| CSRF | Signed token **в сессии** + form / `X-CSRF-Token`; `csrf_cookie` в config **не используется** |
| 2FA | TOTP + backup; device cookie; admin reset; политика для org |
| OAuth state | Signed timed payload с PKCE verifier (не зависит от cookie хоста лендинга) |
| Rate limit | In-memory (login, 2FA, reset, leads, webhook) — не шарится между репликами |
| Org isolation | deps + org_scope + probe route |

**Критичный ops-контракт:** Redirect URI Яндекса и cookie сессии должны жить на **`app.dok.moscow`**, не на лендинге.

## 10. Проблемы и долги (для анализа)

### 10.1. Продукт / UX / перелинковка

| # | Проблема | Влияние |
|---|----------|---------|
| P1 | Нет ссылок **app → лендинг** («На сайт», оферта, поддержка) | Замкнутый кабинет; хуже доверие/SEO-путь пользователя |
| P2 | `/zakon` из кабинета — относительный URL на **app-origin** | Дубли контента на двух хостах или путаница каноникала |
| P3 | Два поиска: `/cabinet/search` и Cmd+K `/api/global-search` | Разный UX и покрытие; риск устаревания HTML-поиска |
| P4 | `NavRole.org_admin` без реальной роли в БД | Нельзя разделить права настроек и обычного пользователя |
| P5 | Upsell подменяет URL пункта меню | Пользователь кликает «Проверка», попадает на биллинг — неочевидно без badge в сайдбаре |
| P6 | Placeholder `/cabinet/org/{id}` в прод-дереве | Мёртвый/тестовый маршрут |
| P7 | Документация ASVS V12.1 «шаблоны вне MVP» vs реализованные org templates | Рассинхрон ТЗ/безопасности |

### 10.2. Технические / ops

| # | Проблема | Влияние |
|---|----------|---------|
| T1 | `Base.metadata.create_all` в lifespan **и** Alembic в entrypoint | Риск скрыть рассинхрон моделей/миграций |
| T2 | In-memory rate limits | Обход после рестарта; не для multi-replica |
| T3 | Мёртвый `csrf_cookie` в Settings | Ложное ощущение double-submit cookie |
| T4 | OAuth Redirect URI / `SESSION_HTTPS_ONLY` должны быть выставлены на VDS вручную | Регрессия логина Яндексом / Secure cookie |
| T5 | Dual-host один процесс | Нужна согласованность URL в Т-Кассе, OAuth, письмах, sitemap |
| T6 | pravo.gov.ru часто по HTTP | MITM/доступность; осознанный компромисс в коде |
| T7 | SQLite lock счётчиков в dev/тестах vs Postgres FOR UPDATE в проде | Параллельная выдача номеров на SQLite хрупкая без `allocation_section` |
| T8 | Не перенесены desktop `autocomplete.py`, `linked.py` (W-00 gaps) | Функциональный разрыв с десктоп-Шаблонером |
| T9 | OpenAPI отключён; мало публичного JSON | Норма для MVP, но усложняет внешние интеграции |
| T10 | ПДн: IP в `events` | PART по ASVS V7.1 |

### 10.3. Уже закрытые классы дефектов (контекст ревизии)

- Yandex callback на чужом хосте → session/PKCE (signed state + URI на app).  
- Session/2FA cookie без Secure → `SESSION_HTTPS_ONLY`.  
- `deploy.sh` не пересобирал Gotenberg с шрифтами.  
- Дыры `ROUTE_EXCEPTIONS` после W-24/W-25/nav.  
- Гонка параллельных номеров в тестах счётчиков.

### 10.4. Рекомендуемые оси анализа (следующие шаги)

1. **Информационная архитектура хостов** — каноникал `/zakon`, единый «маршрутизатор» ссылок public↔app.  
2. **Матрица ACL** — реальные роли org_admin vs user; аудит всех POST.  
3. **Единый поиск** — deprecate `/cabinet/search` или свести к API.  
4. **Схема БД** — убрать/ограничить `create_all` вне тестов.  
5. **Наблюдаемость** — rate limit в Redis/Postgres; алерты биллинга/OAuth.  
6. **SEO** — полнота sitemap (zakon acts?), hreflang/canonical при dual-host.  
7. **Связка НПА ↔ генерация документов** — сейчас слабая; нужна ли глубокая перелинковка.
