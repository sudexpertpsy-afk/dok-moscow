# W-49. Онбординг и переносимость данных: импорт контрагентов, нумерация, выгрузка всего

Цель: путь новой организации «регистрация → первый документ» ≤ 10 минут
и доверие к сервису через право забрать свои данные одним архивом.
Три части — можно сдавать отдельными PR в порядке A → B → C.
Регламент прежний: ветка = сессия Cursor, тесты, тег после зелёного.

---

## A. Импорт контрагентов из Excel / CSV

### A.1. Точка входа
«Контрагенты → Импорт» (кнопка рядом с «Добавить») + шаг онбординга (см. B.3).
Право: org_admin и org_member (импорт — не настройка организации).
Тариф: все, включая «Гость» (снижает порог входа); лимит строк по
тарифу: Гость — 50, платные — 5 000 за файл.

### A.2. Форматы
- XLSX, CSV. Legacy `.xls` (BIFF) **не принимается**: без xlrd (поверхность
  атаки ради формата, который Excel/1С давно отдают как xlsx). Ответ UI —
  действие («Сохранить как → .xlsx») + ссылка на шаблон; событие
  `import.rejected_xls`. Если за квартал доля таких отказов > ~5 % попыток
  импорта — пересмотреть с цифрами.
- CSV: автоопределение кодировки (UTF-8 с BOM и без, cp1251 — Excel
  в русской локали сохраняет именно так) и разделителя (`;` / `,` /
  табуляция). Ошибка кодировки — понятное сообщение, не трейсбек.
- Файл ≤ 5 МБ; > 500 строк — обработка фоновой задачей (jobs W-30)
  с прогрессом, ≤ 500 — синхронно.
- Скачиваемый шаблон «Шаблон_импорта_контрагентов.xlsx»: один лист,
  колонка «Тип» (ФЛ / ЮЛ / Эксперт), остальные — по полям карточки;
  вторая строка — пример; примечания к колонкам (формат ИНН, дат).
- Второй источник — «Из настольного Шаблонера»: `.journal.jsonl`
  (контрагенты из контекстов генерации). `Реестр_договоров.xlsx`
  **не отдельный формат**: на данных УСЭ журнал полнее реестра
  (десятки записей журнала vs единицы строк реестра); заголовки реестра
  (`фио_клиента`, `адрес_клиента`…) уже в словаре синонимов общего
  импорта XLSX — при необходимости файл проходит тем же мастером.

### A.3. Мастер импорта (3 шага, HTMX)
1. **Загрузка и сопоставление колонок.** Автосопоставление заголовков
   по словарю синонимов («ИНН», «инн», «INN»; «ФИО», «Ф.И.О.»,
   «Фамилия Имя Отчество»; «Телефон», «Тел.»…); пользователь может
   переназначить любую колонку из выпадающего списка; неиспользуемые
   колонки — «пропустить». Если нет колонки «Тип» — выбрать тип для
   всего файла, либо авто: ИНН 10 знаков → ЮЛ, 12 → ФЛ/ИП.
2. **Проверка и предпросмотр.** Таблица строк со статусом:
   ✓ готово / ⚠ предупреждение / ✗ ошибка и текстом причины —
   валидаторами ядра (validators.py: контрольные суммы ИНН/ОГРН/
   СНИЛС, КПП, БИК, паспорт, даты, телефон, e-mail). Сводка сверху:
   «готово 312 · с предупреждениями 14 · с ошибками 3».
   Дубликаты против существующей картотеки (ЮЛ — по ИНН+КПП, ФЛ — по
   ФИО+паспорт либо ФИО+дата рождения, эксперт — по ФИО+ИНН):
   переключатель «Дубликаты: пропустить / обновить пустые поля /
   перезаписать» (по умолчанию — обновить пустые). Дубли внутри
   самого файла — объединить, показать.
   Флажок «Обогатить ЮЛ из ЕГРЮЛ (DaData findById)» для строк, где
   есть только ИНН: показать оценку «потребуется N запросов из
   дневного лимита M» (лимит W-21), по умолчанию выключен.
3. **Импорт и отчёт.** Строки с ошибками не импортируются (остальные —
   да, если пользователь не выбрал «только при 0 ошибок»). Транзакция
   на пачку 200 строк. Итог: создано / обновлено / пропущено / ошибок;
   «Скачать отчёт об ошибках (xlsx)» — исходные строки + причина,
   чтобы поправить и загрузить повторно. Запись в events (кто, файл,
   итоги); ПДн в лог не пишутся.

### A.4. Ограничения и безопасность
- Rate limit: 10 импортов в час на организацию (rate_counters).
- Файл импорта — во временный каталог FILES_ROOT/{org}/imports/
  (изоляция хелпером safe_paths), удаляется worker'ом через 24 ч.
- Формулы Excel не исполняются (openpyxl data_only); значения
  приводятся к строкам; ведущие «=», «+», «-», «@» в ячейках
  экранируются при последующем экспорте (CSV-injection).
- Всё в рамках org_id; импорт никогда не трогает чужие организации.

### A.5. Тесты
Кодировки (UTF-8/BOM/cp1251), разделители, автосопоставление
синонимов, валидаторы на плохих строках, три режима дубликатов,
дубли внутри файла, лимиты по тарифу и размеру, фоновая задача
>500 строк с прогрессом, отчёт об ошибках, IDOR (файл импорта чужой
org → 404), journal.jsonl из desktop.

## B. Нумерация при онбординге и в настройках

### B.1. Экран «Нумерация документов» (Настройки → Нумерация)
Таблица всех счётчиков организации (договоры, счета, акты, ПКО,
исходящие письма, заключения — из реестра ключей ядра):
- **Шаблон номера** с токенами `{n}`, `{nn}`/`{nnn}` (с ведущими
  нулями), `{гггг}`, `{гг}`, `{префикс}` (например
  `{префикс}-{гггг}/{nnn}` → `Д-2026/048`) — расширяет
  существующий формат (W-42 «N/ГГ») без слома: по умолчанию текущий.
- **Начать с** — стартовое значение `n` («у нас последний договор был
  № 2026/047 → следующий 048»).
- **Сброс** — никогда / ежегодно (1 января `n` → 1).
- **Предпросмотр**: «Следующий номер будет: Д-2026/048» — считается
  тем же кодом, что и реальная нумерация (один хелпер, тест паритета).
Право: org_admin. Изменение при уже существующих документах —
подтверждение + событие; запрет ставить «начать с» меньше максимума
уже использованного в этом году (иначе дубли номеров) — ошибка
с пояснением.

### B.2. Совместимость
Существующие счётчики организаций не меняются миграцией: шаблон
по умолчанию воспроизводит текущее поведение байт-в-байт (тест на
эталонах номеров). Ключи счётчиков — из реестра ядра, новые шаблоны
(W-42) подхватываются автоматически.

### B.3. Онбординг-чеклист на дашборде
Расширить пустое состояние W-28 до персистентного чеклиста
организации (таблица `org_onboarding` или JSONB в organizations):
1. Реквизиты организации → /cabinet/settings/
2. Нумерация → /cabinet/settings/numbering (B.1)
3. Контрагенты: dual CTA «Импортировать из Excel» → /cabinet/counterparties/import
   и «Добавить вручную» → /cabinet/counterparties/new (см. A)
4. Первый комплект → /cabinet/package/
(+ для платных: 5. Печать и подпись → W-43.)
Шаг помечается выполненным автоматически по факту (реквизиты
заполнены, счётчик изменён или подтверждён «оставить как есть»,
есть ≥1 контрагент, есть ≥1 документ). Чеклист сворачивается после
завершения, «скрыть навсегда» доступно с шага 2.
Метрика на /admin/обзор: медианное время «регистрация → первый
документ» и доля организаций, дошедших до шага 4 (это и есть KPI
пакета: цель ≤ 10 минут).

### B.4. Тесты
Паритет предпросмотра и реальной нумерации; токены шаблона; сброс
1 января; запрет отката ниже использованного; байт-в-байт для
существующих организаций; чеклист — автоотметки и скрытие.

## C. Выгрузка всех данных организации

### C.1. Точка входа
Настройки → «Данные организации» → «Выгрузить всё (архив)».
Право: только org_admin. **Подтверждение TOTP** обязательно (архив
содержит ПДн клиентов организации) — механика W-34/W-38; если 2FA
у org_admin не включена — подтверждение паролем + письмо-уведомление
всем org_admin организации «создана выгрузка данных, инициатор …»
(защита от тихого слива при компрометации одного аккаунта).

### C.2. Содержимое ZIP (формат `dok-export-v1`)
```
dok-export_{org}_{ГГГГ-ММ-ДД}.zip
├── README.txt              # что внутри, как открыть, версия формата
├── manifest.json           # версия формата, дата, org_id, счётчики строк
├── organization.json       # реквизиты и настройки (без секретов/ключей)
├── users.csv / .json       # сотрудники: e-mail, роль, статус (без хэшей)
├── counterparties.xlsx/.json
├── contracts.xlsx/.json
├── documents.xlsx/.json    # метаданные + относительный путь к файлу
├── files/documents/…       # DOCX/PDF как в хранилище
├── templates_org/          # свои DOCX-шаблоны + манифесты
├── fields.json             # словарь своих полей (W-41)
├── branding/               # печать/подписи (W-43)
├── numbering.json          # счётчики и шаблоны номеров
├── calendar.json           # события/напоминания
├── law_bookmarks_notes.json
├── payments.xlsx           # свои платежи (без реквизитов карт — их нет)
└── events.csv              # журнал действий организации
```
Таблицы — XLSX (для людей: русская локаль, ширины колонок) + JSON
(для машин); CSV не основной формат из-за кодировок Excel.
Значения с ведущими `= + - @` экранируются (CSV/XLSX-injection).

### C.3. Механика
- Создание — фоновой задачей (jobs W-30) с прогрессом; архив
  собирается в FILES_ROOT/{org}/exports/, скачивание — авторизованным
  маршрутом через safe_paths; ссылка действует 24 ч, затем worker
  удаляет файл. Лимит: 2 выгрузки в сутки на организацию.
- Событие «экспорт создан/скачан/удалён» с инициатором в events;
  в админке сервиса — счётчик выгрузок (без содержимого).
- Импорт архива обратно — вне скоупа; формат задокументирован в
  docs/формат_экспорта_v1.md, чтобы данные были реально переносимы.

### C.4. Полнота — тест-контракт
Для фикстурной организации: число строк каждой таблицы в архиве ==
числу записей в БД по org_id; каждый файл documents.* присутствует в
files/; в архиве НЕТ ни одной записи другой организации (IDOR-тест на
двух org); нет секретов (grep по ключам/хэшам); README открывается.

### C.5. Связанное (за скоупом, зафиксировать в docs)
Право на удаление: «Удалить организацию и все данные» с 14-дневным
карантином и экспортом перед удалением — отдельный пакет; сейчас
обезличивание контрагентов (W-08) + запрос в поддержку (W-support).

## Витрина и справка
- Лендинг/тарифы: строка «Импорт контрагентов из Excel» и «Выгрузка
  всех данных одним архивом» (второе — в блок «Доверие и
  безопасность»: «ваши данные — ваши»).
- Справка: три статьи — импорт (с шаблоном), нумерация (токены,
  примеры), выгрузка (что внутри, как открыть).

## Оценка и порядок
A — 4–5 дн. · B — 2–3 дн. · C — 3 дн. Порядок A → B → C или B → A → C
(B меньше и сразу улучшает онбординг). Теги v1.2.x по частям.
Критерий пакета: тестовая организация с нуля до первого комплекта
за ≤ 10 минут по секундомеру, с импортом 300 контрагентов из
реального Excel-файла (не из шаблона).
