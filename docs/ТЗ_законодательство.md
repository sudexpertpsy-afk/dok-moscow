# ТЕХНИЧЕСКОЕ ЗАДАНИЕ

Раздел «Законодательство о судебной экспертизе» на dok.moscow

с обновлением редакций из официальных источников государственных органов РФ

Рабочие пакеты W-16…W-19 · реализация в Cursor

ООО «УСЭ» · 1 августа 2026 г. · версия 1.0


## 1. Цель, источники и правовые рамки

### 1.1. Цель

Добавить на dok.moscow публичный раздел «Законодательство» — библиотеку нормативных правовых актов в области судебной экспертизы: профильный закон, «экспертные» нормы процессуальных кодексов, разъяснения высших судов и доступные к публикации ведомственные приказы. Тексты поддерживаются в актуальной редакции на основе официальных государственных источников, с указанием редакции и ссылкой на первоисточник у каждого документа. Раздел открытый (без регистрации): он работает и как справочник для подписчиков, и как SEO-магнит для целевой аудитории.

### 1.2. Итоги исследования источников

- **Официальный интернет-портал правовой информации (pravo.gov.ru).** Государственный первоисточник. Подсистема официального опубликования publication.pravo.gov.ru имеет открытый JSON-API (эндпойнты вида /api/Documents с фильтрами по виду акта, органу, дате, и выдачей PDF официальной публикации). API официально не документирован, но открыт, стабилен и широко используется; агент Cursor обязан проверить актуальные эндпойнты и структуру ответов перед реализацией. Это основной канал МОНИТОРИНГА новых актов и изменений.

- **ИПС «Законодательство России» (pravo.gov.ru/ips).** Государственная система с ДЕЙСТВУЮЩИМИ РЕДАКЦИЯМИ федеральных законов и кодексов (учтены все изменения). Программного API нет — тексты редакций забираются автоматизированно постранично (HTML), аккуратно и с малой частотой. Это источник АКТУАЛЬНЫХ ТЕКСТОВ кодексов и законов.

- **Сайты ведомств и Верховного Суда.** Постановления Пленума ВС РФ — vsrf.ru; приказы министерств, не размещённые на portal publication — официальные сайты Минюста, Минздрава, МВД. Используются как источники для конкретных документов реестра.

- **Правомерность републикации.** Официальные документы государственных органов (законы, иные НПА, судебные решения) НЕ являются объектами авторских прав (п. 6 ст. 1259 ГК РФ) — их тексты можно публиковать свободно. Запрещено копировать тексты «в редакции» из коммерческих систем (КонсультантПлюс, Гарант): сами акты свободны, но их базы данных с редакциями — охраняемый объект. Поэтому редакции берём только из государственных источников.

- **Ограничение по ГОСТам.** Национальные стандарты (например, ГОСТ Р 57344-2016 о терминах СПЭ) свободной републикации не подлежат — в разделе даются карточкой с описанием и ссылкой на официальный фонд стандартов, без полного текста.

### 1.3. Принцип актуализации: полуавтоматический

Полностью автоматическая замена текстов законов — юридически рискованна (ошибка парсинга исказит норму права на публичном сайте). Принимается схема «машина находит — человек подтверждает»: система ежедневно мониторит официальное опубликование по списку отслеживаемых актов, при обнаружении изменения готовит новую редакцию (загруженный текст + сравнение с текущей), а администратор одним действием просматривает и публикует её. У каждого документа на сайте — дата редакции, дата последней сверки и ссылка на первоисточник.

Начальный реестр — Приложение А настоящего ТЗ. Для кодексов принят режим «фрагменты»: публикуются только статьи, относящиеся к экспертизе (перечислены в реестре), с ссылкой «полный текст — в ИПС „Законодательство России“». Это снижает объём мониторинга на порядок и повышает ценность (эксперту нужны именно эти статьи).

Критерии приёмки: миграции; реестр загружен фикстурой; тесты модели версий (одна опубликованная редакция на акт).

### W-17. Загрузчик и мониторинг официальных источников

- **Модуль sources/publication_api.py:** клиент открытого API publication.pravo.gov.ru (агент сверяет эндпойнты по факту): поиск документов по номеру/виду/органу/периоду, метаданные, скачивание PDF официальной публикации. Вежливый режим: не более 1 запроса/сек, кэширование, User-Agent с контактом.

- **Модуль sources/ips_loader.py:** получение действующей редакции закона/статей кодекса из ИПС «Законодательство России» (HTML → очистка → нормализованный HTML). Селекторы вынесены в конфиг — при смене вёрстки ИПС правится один файл.

- **Ежедневная задача мониторинга:** для каждого отслеживаемого акта — проверка новых изменяющих документов в официальном опубликовании (по названию/номеру базового акта); при находке — создание черновика новой редакции: автозагрузка текста из ИПС (когда редакция там появится), diff со старой редакцией, письмо администратору «Обнаружено изменение N-ФЗ от …».

- **Отказоустойчивость:** ошибка источника не роняет задачу (запись в act_watch_log, повтор завтра); три ошибки подряд по одному акту — письмо администратору.

Критерии приёмки: на тестовом наборе (закреплённые фикстуры ответов API и страниц ИПС) загрузчики выдают корректный текст; мониторинг находит подложенное «изменение» и создаёт черновик с diff; ограничение частоты запросов соблюдается (тест).

> **Промпт для Cursor (режим Agent):**
>
> *Реализуй W-17 по docs/ТЗ_законодательство.md. Сначала исследуй фактическое API publication.pravo.gov.ru (открытые JSON-эндпойнты /api/…): найди рабочие методы поиска документов и получения PDF, зафиксируй их в docs/источники_НПА.md с примерами ответов. Затем: sources/publication_api.py (httpx, троттлинг 1 rps, кэш), sources/ips_loader.py (загрузка действующей редакции из pravo.gov.ru/ips, селекторы в конфиге), ежедневная задача мониторинга с созданием черновиков редакций и diff (difflib, ndiff по абзацам), письма администратору. Тесты на фикстурах, сеть в тестах замокана. Прогони pytest.*

### W-18. Публичный раздел «Законодательство»

- Каталог /zakon: группировка по категориям (Профильный закон · Процессуальные кодексы · Разъяснения высших судов · Ведомственные приказы · Стандарты); карточка: название, номер/дата, орган, дата актуальной редакции, дата последней сверки.

- Страница акта /zakon/\<slug\>: нормализованный текст (для кодексов — «экспертные» статьи с оглавлением), плашка «Редакция от … · сверено … · первоисточник: официальный интернет-портал правовой информации (ссылка)»; кнопка «PDF официальной публикации» (если есть); архив предыдущих редакций.

- Поиск по текстам раздела (PostgreSQL full-text, русская морфология) с подсветкой найденного.

- SEO: ЧПУ-адреса, теги title/description по шаблону, микроразметка, sitemap, перелинковка с лендингом; дисклеймер в подвале раздела: «Тексты приводятся в справочных целях по официальным источникам и не являются официальным опубликованием».

- Для подписчиков — сквозные ссылки из кабинета: на странице шаблона документа блок «Нормативная база» (например, у договора на экспертизу — ст. 79 ГПК, ст. 41 73-ФЗ).

Критерии приёмки: раздел открывается без входа; поиск «внушаемость» и «дополнительная экспертиза» возвращает релевантные статьи; PageSpeed ≥ 85; в подвале каждого текста — источник и даты.

### W-19. Админка раздела и регламент актуализации

- Раздел админ-панели «Законодательство»: список актов с индикаторами (зелёный — сверено \< 30 дней; жёлтый — ожидает подтверждения новая редакция; красный — ошибка источника); карточка акта: черновик новой редакции с diff-просмотром (удалено красным, добавлено зелёным), кнопки «Опубликовать редакцию» / «Отклонить»; ручная загрузка текста (для приказов, недоступных программно) с обязательным полем «источник».

- Управление реестром: добавить акт, изменить режим (полный/фрагменты/карточка), список отслеживаемых статей кодекса, снять с отслеживания (статус «утратил силу» с сохранением архива — эксперту нужны и старые редакции для дел прошлых лет).

- Журнал всех публикаций редакций в events (кто, когда, что изменилось).

- Регламент в docs/регламент_НПА.md: ежемесячная ручная сверка «жёлтых» и «красных»; порядок действий при крупных реформах (новая редакция целиком).

Критерии приёмки: сценарий «мониторинг нашёл изменение → письмо → diff в админке → публикация» проходит без правки кода; непроверенные черновики не видны на публичном сайте.
