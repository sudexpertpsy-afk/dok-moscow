# Регламент актуализации раздела «Законодательство»

ООО «УСЭ» · Док.Москва · пакет W-19

## 1. Роли

| Роль | Действия |
|------|----------|
| Система (worker) | Ежедневный мониторинг официального опубликования; создание черновиков; письма администратору |
| Администратор сервиса | Просмотр diff, публикация / отклонение, ручная загрузка, правка реестра |
| Владелец (эксперт) | Ежемесячная ручная сверка «жёлтых» и «красных»; вычитка фрагментов кодексов |

## 1a. Первичное наполнение реестра

1. В админке `/admin/legal/` → **Наполнить из ИПС** (или на карточке акта → **Загрузить из ИПС**).
   Для актов с `eo_number` без `ips_nd` подтягивается PDF с publication.pravo.gov.ru.
2. CLI: `cd web && PYTHONPATH=. python scripts/bootstrap_legal_texts.py`
   (нужен доступ к pravo.gov.ru/ips и/или publication.pravo.gov.ru).
3. Создаются **черновики**; для `fragments` заполняются найденные статьи.
4. Администратор/владелец проверяет diff и публикует по §3. Автопубликации из мониторинга нет.
5. Пакетная публикация первичного наполнения (осознанно): кнопка **Опубликовать черновики**
   в `/admin/legal/` (только акты без published) или CLI  
   `PYTHONPATH=. python scripts/publish_legal_drafts.py`  
   либо bootstrap с флагом `--publish`.
6. Акты без `ips_nd`/`eo_number` и режим `card` — только ручная загрузка или правка ссылки
   (пленумы ВС/ВАС, 346н, 511, свод СЭУ Минюста).

## 2. Ежедневный контур (автомат)

1. Worker запускает `run_daily_watch`.
2. При находке изменяющего документа создаётся **черновик** редакции (`act_versions.status=draft`) с `diff_text`.
3. Администратору уходит письмо со ссылкой на `/admin/legal/`.
4. Черновик **не** попадает в `/zakon` и поисковый индекс, пока не опубликован.

Индикаторы в `/admin/legal/`:

- **зелёный** — сверка &lt; 30 дней, нет черновика и ошибок;
- **жёлтый** — есть черновик (нужно подтвердить или отклонить);
- **красный** — ошибка источника (в т.ч. 3 подряд);
- **серый** — нет свежей сверки / мониторинг выключен.

## 3. Подтверждение редакции

1. Открыть акт → блок «Черновик» → просмотреть diff (удалено красным, добавлено зелёным).
2. При необходимости раскрыть полный HTML черновика.
3. **Опубликовать** — прежняя published → archived; индекс поиска пересобирается; `last_verified_at` обновляется. Событие `legal_version_published` в `events`.
4. **Отклонить** — черновик → archived; на сайте без изменений. Событие `legal_version_rejected`.

## 4. Ручная загрузка

Для приказов и актов без стабильного API:

1. Карточка акта → «Ручная загрузка текста».
2. Обязательно поле **Источник** (URL или реквизиты официального опубликования).
3. Создаётся черновик с diff относительно текущей published; далее — как в §3.

## 5. Ежемесячная ручная сверка

До 5-го числа каждого месяца администратор/владелец:

1. Открывает `/admin/legal/`, фильтрует глазами жёлтые и красные.
2. Жёлтые — закрывает публикацией или отклонением.
3. Красные — проверяет доступность pravo.gov.ru / ИПС; при смене вёрстки правит селекторы в `sources/`; при устойчивом отказе — ручная загрузка или временно `watch_enabled=off` с заметкой в notes.
4. Выборочно сверяет 2–3 ключевых акта (73-ФЗ, УПК/ГПК фрагменты) с первоисточником даже при зелёном индикаторе.

## 6. Крупные реформы (новая редакция целиком)

1. Дождаться появления текста в ИПС или взять официальный PDF.
2. Ручная загрузка полного HTML (или загрузчик IPS, если доступен `ips_nd`).
3. Diff будет большим — просмотреть выборочно ключевые статьи; для режима `fragments` обновить `tracked_articles` и тела фрагментов.
4. Опубликовать одним действием; старая редакция остаётся в архиве (нужна для дел прошлых лет).
5. Статус `repealed` — только если акт утратил силу целиком; архив редакций не удалять.

## 7. Критерий качества

Непроверенные черновики никогда не видны на `dok.moscow/zakon`. Публикация — осознанное действие администратора с записью в `events`.
