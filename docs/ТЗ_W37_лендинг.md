# W-37. Редизайн лендинга dok.moscow: польза, доказательства, конверсия

Принципы: меняются ТОЛЬКО шаблоны landing/*, стили и статика публичной
части. Маршруты, структура приложения, кабинет — без изменений.
Тексты секций — через слоты content_blocks (W-36), чтобы владелец
правил их без деплоя. Производительность: PageSpeed mobile ≥ 90.

## 1. Диагноз текущей версии (что чинить)

- Hero: абстрактные «листы» выглядят как заглушка; заголовок = название
  продукта, а не выгода; нет продукта «в лицо» (скриншота кабинета),
  нет строки доверия. 80% первого экрана — пустой фон.
- Раздел «Примеры документов» — три текстовые строки с линейками:
  выглядит как пустой список, документы не показаны.
- Тарифы — три колонки текста без карточек, выделения и кнопок CTA.
- Отсутствуют целиком: проблема→решение, «как это работает», функции,
  «для кого», цифры, доверие/безопасность, FAQ. Посетитель не может
  понять возможности сервиса, не войдя в кабинет.

## 2. Новая структура страницы (сверху вниз)

Каждая секция отвечает на следующий вопрос посетителя. Один основной
CTA («Запросить ранний доступ»; после запуска оплаты — «Попробовать
бесплатно») повторяется 3 раза: hero, после возможностей, финал.

### 2.1. Hero
- Заголовок (слот hero_заголовок), вариант по умолчанию:
  «Комплект документов экспертизы — за 5 минут вместо часа»
- Подзаголовок: «Договор, счёт, акт и кассовый ордер по шаблонам,
  выверенным практикующей судебно-экспертной организацией. Реквизиты
  заказчика — из ЕГРЮЛ по одному ИНН. Сроки договоров — под контролем.»
- Справа/фоном — РЕАЛЬНЫЙ скриншот кабинета (мастер комплекта, шаг 2)
  в аккуратной браузерной рамке, лёгкий наклон/тень. Никаких
  абстрактных иллюстраций. Скриншот делается с демо-организации
  (обезличенные данные), файл — static/img/hero-app.webp.
- Кнопки: [Запросить ранний доступ] [Примеры документов ↓]
- Строка доверия под кнопками, мелко: «Сделано экспертами ООО «УСЭ»
  (лицензия ЛО-77-01-017900) · Данные хранятся в России · 152-ФЗ»

### 2.2. «Знакомо?» — проблема (3 карточки)
1) «Новый договор — снова копирование реквизитов из прошлогоднего
   файла и страх пропустить чужую фамилию в тексте»
2) «Опечатка в ИНН или номере договора всплывает уже в суде»
3) «Срок договора истёк, акт не подписан — заметили через месяц»
Подпись: «Док.Москва закрывает это системно — ниже как.»

### 2.3. «Как это работает» — 3 шага (скриншот к каждому)
1) «Введите ИНН — карточка заказчика заполнится из ЕГРЮЛ сама»
2) «Отметьте состав комплекта — договор, счёт, акт, ПКО»
3) «Скачайте DOCX или весь комплект одним PDF — с вашей нумерацией»
Под шагами: «Средний комплект — 4 документа за 5 минут.»

### 2.4. Возможности (6 карточек, иконки строгие, без стока)
- Комплекты документов: договор+счёт+акт+ПКО одной формой; нумерация
  и журнал — автоматически
- Картотека и ЕГРЮЛ: повторный клиент — два клика; статус юрлица
  (ликвидация/банкротство) виден до договора
- Календарь сроков: истечения договоров и неподписанные акты — на
  главном экране, а не в памяти
- Нормативная база: 73-ФЗ, «экспертные» статьи кодексов и приказы —
  в актуальных редакциях, с уведомлениями об изменениях
- Проверка контрагента: полная карточка из ЕГРЮЛ с руководителем —
  должная осмотрительность с журналом проверок
- Свои шаблоны (тариф «Организация»): загрузите фирменные DOCX —
  сервис заполняет их как родные

### 2.5. «Для кого» (3 колонки)
- Частный эксперт: «вся бумажная рутина практики — в одном кабинете»
- Экспертная организация: «до 5 сотрудников, общая картотека, свои
  шаблоны и реестры»
- Учебный центр ДПО: «договоры на обучение и комплекты к ним»

### 2.6. Цифры (полоса)
«26 шаблонов · комплект за ~5 минут · реквизиты из ЕГРЮЛ без ручного
ввода · документы в DOCX и PDF»

### 2.7. Примеры документов — ПЕРЕДЕЛАТЬ в карточки
Три карточки с миниатюрой первой страницы PDF (картинка!), названием
и кнопкой «Открыть PDF». Миниатюры генерирует scripts/make_samples.py
(pdftoppm первой страницы → webp 480px). Подпись про водяной знак
оставить.

### 2.8. Доверие и безопасность (4 пункта в строку)
Сервер в РФ · шифрованные резервные копии ежедневно · 152-ФЗ,
политика ПДн · двухфакторный вход и Яндекс ID

### 2.9. Тарифы — карточки
Три карточки с рамками и тенью; «Специалист» — акцентная рамка и
бейдж «Популярный»; в каждой — список включённого (✓-строки) и
кнопка CTA; переключатель Месяц/Год («год = −2 месяца») после
запуска оплаты. Данные — из таблицы tariffs (W-36), не хардкод.

### 2.10. FAQ (аккордеон, 6 вопросов)
- Чем это лучше Word-шаблонов на моём компьютере?
- Мои данные и данные моих клиентов — где они хранятся?
- Можно ли загрузить собственные шаблоны?
- Что будет с документами, если я перестану платить?
  (ничего не теряется: просмотр и скачивание остаются)
- Подходит ли сервис не судебным экспертам?
- Как попасть в бету?

### 2.11. Финальный CTA + форма раннего доступа
Заголовок: «Первые 20 подписчиков беты — 50% навсегда».
Форма как сейчас (e-mail, профиль, комментарий) + строка про ПДн.

## 3. Визуальный стиль

- Палитру (тёмно-зелёный/кремовый) сохранить — она удачная; добавить
  контрастный акцент для CTA и бейджей.
- Типографика: нынешняя антиква в заголовках остаётся фирменной чертой;
  поднять контраст размеров (h1 ≥ 56px desktop), плотнее вертикальный
  ритм — сейчас пустоты больше, чем контента.
- Все изображения: WebP, width/height заданы (без CLS), lazy ниже fold;
  критический CSS — инлайном (совместимо с W-31).
- Никаких каруселей, видео-фонов и тяжёлых анимаций; допустимы
  лёгкие hover и появление секций (prefers-reduced-motion уважать).

## 4. Технические требования

- Только landing/*-шаблоны, CSS и static/img; diff остальных шаблонов
  и маршрутов = 0 (тест).
- Тексты всех секций — слоты content_blocks с fallback (W-36-совместимо;
  если W-36 ещё не влит — тексты в шаблоне, слоты добавить при W-36).
- Скриншоты кабинета: сделать по чек-листу docs/скриншоты.md
  (демо-организация «Экспертный центр Пример', обезличенные данные,
  окно 1440×900, светлая тема) — 4 файла: hero, шаги 1–3.
- /tariffs: расширить сравнительной таблицей функций по тарифам
  (строки: комплекты, картотека, ЕГРЮЛ-проверка, календарь, свои
  шаблоны, пользователи, поддержка).
- SEO: заголовки h1–h3 согласованы с ключами («документы судебного
  эксперта», «договор на экспертизу», «комплект документов
  экспертизы»); существующие мета и канониклы не трогать.

## 5. Критерии приёмки

- PageSpeed mobile ≥ 90, desktop ≥ 95; LCP — hero-скриншот ≤ 2,0 с.
- На первом экране без скролла: выгода, продукт (скриншот), CTA,
  строка доверия.
- Посетитель, не входя в кабинет, может назвать ≥ 5 возможностей
  сервиса (все секции 2.3–2.4 присутствуют и наполнены).
- Примеры — с миниатюрами; тарифы — карточками с CTA.
- Мобильная вёрстка: все секции читаемы на 375px, CTA — палец.
- Тест: маршруты и не-landing шаблоны не изменены.

Коммит: «W-37: редизайн лендинга». Оценка: 4–6 дн.
Зависимости: мягкие — W-36 (слоты, тарифы из БД), W-31 (кэш/сжатие);
можно делать до них с fallback-текстами в шаблонах.
