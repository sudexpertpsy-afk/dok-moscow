# Инцидент: поток алертов «Ошибки вебхука Т-Кассы» (2026-08-08)

## Симптом

Почасовые письма `[Док.Москва] Ошибки вебхука Т-Кассы` с текстом
«Подряд отказов: 3. Последняя причина: Неизвестный OrderId», IP
`91.194.226.250`. Gmail начал блокировать доставку из‑за частоты.

Подпись Token валидна (иначе причина была бы «Неверная подпись») —
источник уведомлений: Т-Банк, не атака.

## Диагностика

| Поле | Значение |
|------|----------|
| Event | `#254` `billing_webhook_rejected` |
| OrderId | `probe-w45-435ed6f1-125a-42e4-9ea5-3ca7f1ffc252` |
| Status (банк) | `CANCELED` |
| PaymentId | `9006497914` |
| Запись в БД | нет (OrderId не UUID платежа) |
| GetState | `Status=CANCELED`, `Amount=0` — денег нет |
| Маркер `webhook_fail` | `streak=3`, reason=`Неизвестный OrderId` |

Исход **1(а)**: осиротевшее уведомление по probe Init+Cancel из админки
«Проверить подключение». Probe создавал платёж с `NotificationURL` на
наш вебхук и `order_id=probe-{uuid}` вне таблицы `payments` →
`TBankError("Неизвестный OrderId")` → `record_webhook_fail` → streak
не сбрасывался (успешных вебхуков не было) → `check_alerts` слал
письмо каждый час (cooldown 1 ч).

Банку уже отвечалось `OK` (`billing.py`); поток писем — от алерт-логики,
не от HTTP-ретраев с ошибкой.

## Исправления (HOTFIX)

1. Вебхук: WARNING с OrderId/PaymentId/IP; ACK `OK` на неизвестный
   OrderId / платёж не найден (как и раньше по HTTP).
2. Алерты: security vs operational; operational только счётчик на
   `/admin/status`; тихий период по умолчанию 6 ч; тумблер в
   «Платёжная система».
3. Probe Init без `NotificationURL`.
4. Удаление организации: запрет при `created`/`authorized` +
   `tbank_payment_id`.
5. Документация SPF/DKIM/DMARC (`docs/почта_spf_dkim_dmarc.md`).

После деплоя: сброс маркеров `webhook_fail` / `alert_webhook_fail` на
проде (streak от probe больше не должен алертить).
